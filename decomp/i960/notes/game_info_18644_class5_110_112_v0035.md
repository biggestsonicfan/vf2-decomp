# `fa_game_info` `0x18644`: class 5 representative (`0x110<->0x112`)

This note records ROM-backed recovery of the class-5 state-space representative `0x110/0x112` and its reverse orientation.

The fighter state values are read from the real `fighter + 0x1a4` fields. The pure-ROM caller-to-task vector is `(213, 218, 213, 218)` for `(countdown=0/mode6=0, countdown=0/mode6=1, countdown=1/mode6=0, countdown=1/mode6=1)`.

The exact pair was admitted only in the existing bilateral gate, bit1-specific gate and final threshold guard. Initial differential probes showed CPU state and mutable memory exact in all 16 isolated cases (two orientations x two call sites x countdown x mode bit 6); procedure calls and returns were already exact.

Instruction accounting is orientation- and call-site-specific. A first accounting attempt exposed that the internal `r7/r8` role at the second call is reversed relative to the starting orientation even though the underlying `fighter+0x1a4` memory remains unchanged. The final recovery therefore keeps the first-call table by current orientation and swaps the second-call correction table.

Final isolated validation is 16/16 exact: CPU state, mutable memory, executed instructions, procedure calls and procedure returns all match the pure ROM.

Final chained validation executed `native 0x18644 #1 -> caller ROM -> native 0x18644 #2 -> tail ROM -> 0x10dcc` for both orientations and all countdown/mode-bit-6 combinations. All eight cases match the pure ROM exactly, with final instruction totals `14275969` for mode bit 6 clear and `14275974` for mode bit 6 set, and `10249/10248` procedure calls/returns.

# Selector 17 index 6 validation

BOOKKEEPING 1/5 is recovered and strict-snapshot validated from clean `0x0000a6c0` boundaries. The `a5=0` layout and `a5=1` empty/default value phase consume 15309/25 and 1815/79 instructions/calls respectively, with one additional procedure return at the frame boundary. The renderer preserves fixed ROM tile attribute spans; the undefined PLAY TIME RATIO field is centered at columns 35..38 inside a highlighted 33..38 value span.

BOOKKEEPING 2/5 is represented by the same two-phase state machine. `a5=2` lays out GLOBAL DATA 2 / TYPE-B DATA and advances to `a5=3`; its measured frame consumes 15175 instructions and 40 nested calls. `a5=3` renders the empty/default counters, average-time placeholders and 21-row four-column duration histogram; it consumes 3626 instructions and 128 nested calls. The layout phase matches the ROM snapshot exactly. The data renderer follows the ROM's right-aligned numeric fields: START/CONTINUE totals end at columns 40/53, average-time placeholders begin at 35/48, and histogram zeros occupy columns 21/33/45/56 inside independent six-cell highlighted spans.

BOOKKEEPING 3/5 is recovered as states `a5=4/5`. The layout phase contains the 1P GAME DATA summary plus an eleven-round COUNT/TIME/WIN RATE table; the empty/default phase renders zero counters, zero/minimum times and undefined averages/rates. Measured execution is 14911 instructions/32 nested calls for the layout transition and 3122/99 for the data phase. Each round keeps four independent six-cell value spans after its round-number field, matching the descriptor-oriented ROM renderer rather than treating the row as one formatted string. The initial implementation also exposed a GCC-only `-Wmisleading-indentation` warning in the compact helper epilogue; the helper has been expanded to normal block form so the warnings-as-errors matrix remains clean.

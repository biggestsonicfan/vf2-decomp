Adjacent to the already admitted `0x24004140` (state8 + bits 6+14+21+26+29).

* `trace_case.py` with `fighter0_flags=0x24004144` / `fighter1_flags=0x24004144` (adds low bit 2 to the 0x24004140 family)

```

unilateral 0x24004140: run 203, exec 14275959
```

The extra low bit 2 does not change instruction accounting for this high-bit
family (unlike the bit1 variant `0x24004142` which is 211). The stale-frame
postconditions remain those of the `0x24004140` family:
`r3=0x41000000 r4=0x07800f0f r7=0x41000000` with bilateral
`r8/r12/r13` etc. as in `hybrid.c:15555`.

## Recovery
`src/recovered/hybrid.c:15552` now admits both:
```c
combined_positive_bit6_flags == 0x24004140 ||
combined_positive_bit6_flags == 0x24004144
```
sharing the same `native_instructions += bilateral?4:2` and stale-frame
logic. Previously only `0x24004140` was admitted (v0161); `0x24004144`
was `VF2_ERROR_UNSUPPORTED`.
